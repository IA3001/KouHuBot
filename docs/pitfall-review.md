## 隔离的历史已验证条目

以下 8 条完整迁入候选，未修改原题面、答案、修复、case、source 或 verified。问题原因同步记录在其 review.note 中。

| ID | 已证实的问题与复核方向 |
| --- | --- |
| `unsigned-hash` | 修复先计算有符号 `x * 131`，之后才转 unsigned；`x=INT_MAX` 时转换之前已有有符号溢出 UB。原 case 的 `x=-5` 不覆盖此问题。应在乘法之前转换并澄清期望模语义。 |
| `sort-pair-default-lexicographic` | fix 用仅比较 first 的 `std::sort`，不能保证 case 所期望的并列项原始次序。要求稳定性时应使用 `stable_sort`；当前一次输出吻合不能证明契约成立。 |
| `shift-vs-div-negative` | 声称 `-2` 落在 `[-3,0]` 之外，与区间包含关系矛盾；case 只展示除法与右移差异，未证明题干所称越界。 |
| `complement-is-not-negation` | 声称 `x=-1` 时结果碰巧正确；实际 `~(-1)=0`、`-1+0=-1`，不满足和为 0。 |
| `pow2-test-accepts-zero` | 将 1 列为 2 的正整数次幂，但 1 是零次幂；答案还将 `INT_MIN-1` 按回绕解释，忽略有符号减法溢出 UB。 |
| `acos-domain-nan` | “NaN 参与任何比较都是 false”不成立：`NaN != NaN` 为 true。答案还泛化至零向量夹角而未说明其数学定义缺失。原非零向量 case 不能支持这些结论。 |
| `char-mapped-to-zero` | 将根因归为字符映射不单射，但 `a..z -> 0..25` 本身是单射；问题发生在变长字符串的前导零编码。 |
| `even-base-natural-overflow` | 推广称超出 `ceil(64/k)` 长度后“前 ceil(64/k) 个字符全部失效”。base=256、长度9时只有首字符指数达到8，其余前部字符仍有贡献；应按每个位置指数判断。 |

## 保留条目的验证限制

正式库 42 条仅继承已有反例证据，尚有下述边界；本次没有把旧标记提升为全面正确性结论。

- `long-long-mod` 的 buggy 涉及有符号乘法溢出 UB。特定编译器输出不是 C++ 保证，旧期望值不能跨优化级别／编译器泛化；没有为其宣称 sanitizer 已验证。
- `negative-shift-right-floor` 使用 C++17 时负数右移仍有实现相关边界；`one-shl-31-sign-bit` 依赖 32 位 int；`popcount-truncates-longlong` 依赖 GCC 内建函数位宽；输入格式反例中的 `fmemopen` 依赖 GNU/POSIX 环境。
- `assign-vs-equal` 的期望值依赖既有 C 库 rand 序列；浮点输出、舍入和 `unordered-set-prime-multiple-keys` 的桶分布也受平台／标准库／舍入环境影响。pb_ds 条目使用 GNU 扩展。
- `memset-wrong` 仅展示按字节填充与按元素填充之别，旧答案“只能填 0 和 -1”是过度概括。`iterative_segtree_build_top_down` 的“所有内部结点都成 0”也过强，靠近叶层的结点可得到正确和；原 case 已显示部分查询正确。这两条过度概括文字已限定为本例条件，修订号已增加，现存 fix 与各自反例的主要结论一致。
- `printf-half-even-rounding` 的 fix 限非负、适当值域；`pbds_order_of_key_strict_less` 的 `x+1`、`pbds_split_le_boundary` 的 `k-1` 不能扩展到整数极值；`int-div-lose-fraction` 未覆盖分子整数加法溢出；`table-zero-means-empty` 仍要求表未满且无删除操作；`discrete-gap-on-compressed-ranks` 的 fix 跳过重复时刻，需要先明确需求是不同时间值间距。这些额外条件未由既有 case 穷尽。
- 验证器已由子串匹配改为 stdout 完整匹配或显式 stdout_line 整行匹配，并要求正常退出。42条严格行为复验通过；旧 verified 标记和本次反例仍不证明所有解释、所有输入或资源边界均正确。
