# KouHuBot Sprint 计划

建立日期：2026-11-10
基线版本：0.7.0

## 执行约定

- 按目标划分 Sprint，不预设未经估算的截止日期。
- 每次只推进一个 Sprint；新增需求先放 Backlog，阻塞当前目标的缺陷除外。
- 一个任务完成意味着实现、必要测试、文档均完成；一个 Sprint 发布还需完成镜像验证、版本日志、代码与镜像推送。
- 任务状态以本页复选框为准。Sprint 1 已实施，交付版本为 0.7.2。
- 不为新功能升级 SCHEMA_VERSION 导致清空已有积分；新增表与迁移必须保留旧数据。

## Sprint 1：已有功能可信、规则一致

状态：已完成，交付版本 0.7.2（2026-11-10）

目标：修复已有榜单查询失败和未结束题目的信息泄露，使规则、帮助和 ask 回答一致。

### S1-01 统一积分榜数据契约（P0）

- [x] 核对 leaderboard 返回字段与所有调用方，修复 total / total_score 不一致。
- [x] 修复 ask 状态快照及排行榜图片失败后的文字兜底。
- [x] 统一榜单人数配置的默认值与有效范围。
- [x] 测试空榜、多人有成绩、同分排序、图片渲染失败、异常配置。

验收：真实有成绩时 rank 和 ask 显示一致；排序遵循现有规则：总分降序、解题数降序、首次提交 AC 数降序。排序字段完全相同时不擅自新增胜负规则。图片失败仍可读文字榜单。

### S1-02 统一未结束题目的信息隐藏（P0）

- [x] 盘点题面、cur、ask、hint、status、榜单、日志转述等用户可见入口。
- [x] 区分群整体难度进度与当前题目的元数据；明确各入口可公开的内容。
- [x] 未结束题目的题号、标题、实际 rating、具体分值和来源链接不进入 ask 上下文。
- [x] 检查题面图片、文件名以及模型提示的元数据，避免旁路泄露。
- [x] AC / giveup 后按现有约定公开题目信息，不影响揭晓流程。

验收：直接问及诱导 ask 均无法从快照获得受限信息；cur、hint 与两条题目线路同时存在时也保持一致。模型根据题面自行推断难度不等同于元数据泄露，不声称能完全阻止推断。

### S1-03 建立统一规则与功能说明（P1）

- [x] 从 scoring 的现有常量构造计分与升降档说明，避免复制数值后走样。
- [x] 整理唯一的功能说明来源，供帮助与 ask 使用，覆盖 hint、ver 和 grm。
- [x] 新增 rules 命令，直接展示计分、排名、升降档、提示及 grm 规则。
- [x] 明确当前行为：答错不扣分、同一玩家同题只计首次 AC、群题首个 AC 后结束；hint 群内可见且不扣分；grm 不计分。
- [x] ask 回答“rank 怎么算”“hint 扣分吗”“怎么升档”时有完整事实依据。

验收：规则数值与实际实现一致；群整体档位说明不暴露当前题目受限元数据；新指令有帮助入口。此任务不调整现有计分策略。

### S1-04 回归与发布（P0）

依赖：S1-01、S1-02、S1-03。

- [x] 加入有成绩榜单、两槽位同时开题、提示后换题等真实状态场景。
- [x] 对 ask 检查输入上下文，不能只依靠模拟模型输出证明正确。
- [x] 验证升级前后玩家积分、题目状态、已出题记忆和提示缓存保留。
- [x] 完成单元测试、模拟群聊与容器升级验证。
- [x] 更新 CHANGELOG 与内嵌副本，构建并推送新版本镜像和代码。

Sprint 完成标准：上述全部任务验收通过；提供实际输出示例与验证结果，不留已知阻塞缺陷。

不在本 Sprint：题后解析、申诉、个人训练、周期榜、积分玩法改动。

验收记录：单元测试 178 项、群聊测试 236 项通过；从 0.7.1 镜像生成数据卷升级至 0.7.2，确认积分、开放题目、正题/坑点出题记忆及提示缓存保留，有成绩的 ask 快照可读。群档位仍为公开进度；模型从题面推断算法或难度不在确定性遮蔽保证内。

## Sprint 2：做完一道题后能复盘

状态：已完成，交付版本 0.8.0（2026-11-10）。

目标：做题记录和解析可回看，并能说明答案来自哪里。

- [x] S2-01 定义题目轮次、提交、判词与结果的关联；保留旧记录兼容性。
- [x] S2-02 新增 sol，只有题目结束后才能查看；本版明确仅提供模型解析，未接入官方题解获取，不伪装官方来源；生成失败明确提示。
- [x] S2-03 新增个人 history，分页查看近期题目、判定与得分；正题与 grm 分开。
- [x] S2-04 记录主动查看提示的级别与时间，个人战绩区分主动请求与未请求；群内提示公开，不能把未请求直接判为独立完成；积分不变。
- [x] S2-05 回归和发布。

验收记录：178 项单元检查、7 项独立存储测试、254 项群聊检查通过。以 0.7.2 镜像生成旧数据卷升级到 0.8.0，确认积分、当前题、出题记忆和提示缓存保留，旧提交只导入一次；无法恢复的正文、判词、得分和提示使用状态明确标注。解析缓存重启后保留；同题重新开放时封闭历史解析和详细回放。

验收：同一用户能追溯“做了哪道题、提交什么、为何判定、用了什么提示”；解析不会提前泄露正在进行的题；访问范围与群/用户隔离规则明确。

## Sprint 3：错误可反馈、判定可复核

状态：已完成，交付版本 0.9.0（2026-11-10）。

目标：对错题和争议判定有处理闭环。

- [x] S3-01 新增 report，保存题面、翻译、公式、答案等问题反馈。
- [x] S3-02 新增 appeal，关联原提交、原判词与复核结果；添加限流和重复请求控制。
- [x] S3-03 建立管理员待处理列表及处理状态，保留审计记录。
- [x] S3-04 问题题目可暂停抽取，修订后再启用。
- [x] S3-05 回归和发布。

实现约定：report [grm] 描述 关联当前题；appeal [grm] 记录号 理由 仅处理自己的已结束提交。每条提交只接受一次申诉，模型失败转人工；同题待处理反馈不重复登记。数据库限制每群每人每线路每小时5张工单。tickets [grm] 查看自己工单，管理员用 pending、resolve/reject、pause/unpause 处理。暂停作用于本群本线路后续抽取，不强制结束当前题；处理说明不能替代实际题库修订。

验收记录：178 项单元检查、15 项存储测试和272项群聊检查通过；0.8.0 数据卷升级至0.9.0验证原积分、题目、提交、提示、解析保留，新工单、复核快照、处理审计和暂停状态重启后保留。验证他人/跨群工单隔离、管理员权限、重复申诉不调用模型、模型失败保留工单、正题/坑点暂停排除。

验收：反馈有编号、状态和处理记录；复核模型的意见不自动覆盖历史分数。积分更正涉及哪些人、题目是否重开，须先形成明确策略再实施。

## Sprint 4：坑点题库可持续维护

状态：已完成，交付版本 0.10.0（2026-11-10）。

目标：有来源、验证和审核的入库流程，逐步提高题库质量。

- [x] S4-01 候选题与正式题库分离，保存来源链接、采集时间、许可或引用要求及改写记录；历史缺失来源明确 unknown。
- [x] S4-02 统一题目结构、稳定 ID 与修订版本；检查重复、答案泄露和分类一致性。
- [x] S4-03 改进验证器，区分编译、行为验证和依赖 UB 的验证局限；不把未验证直接称为错误或正确。
- [x] S4-04 分批审核现有未验证条目；53条证据不足保留候选，8条发现矛盾隔离，42条严格反例复验通过，不以凑数量代替审核。
- [x] S4-05 增加专题覆盖统计与入库报告，完成回归和发布。

验收：正式42条、候选61条，保留全部103个原ID。工具提供 check/migrate/report/stage/approve/rollback，入库要求来源说明、审核记录和重新运行行为证据，写入前保存SHA快照。历史来源不明仍是已知限制，不伪造授权。维护流程见 pitfall-maintenance.md，审计见 pitfall-review.md，覆盖见 pitfall-coverage.json。

全项目集成验证：30项工具/存储测试、178项单元检查、272项模拟群聊检查通过；42条正式题全量编译与行为反例通过。0.9.0数据卷升级到0.10.0验证积分、历史、提示、解析、工单、审计和暂停状态保留。未连接真实QQ/真实模型服务；没有宣称跨平台穷尽验证或sanitizer全覆盖。Sprint 1–4均完成，Backlog仍为待评估，不纳入已承诺Sprint。

验收：新题经过候选、验证、审核再发布；来源可追踪，问题可回滚。数量目标根据审核通过率制定，不按生成条数认定完成。

## Backlog：待评估，不承诺交付
