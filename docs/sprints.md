# KouHuBot Sprint 计划

建立日期：2026-11-10
基线版本：0.7.0

## 执行约定

- 按目标划分 Sprint，不预设未经估算的截止日期。
- 每次只推进一个 Sprint；新增需求先放 Backlog，阻塞当前目标的缺陷除外。
- 一个任务完成意味着实现、必要测试、文档均完成；一个 Sprint 发布还需完成镜像验证、版本日志、代码与镜像推送。
- 任务状态以本页复选框为准。当前只完成规划，尚未实施 Sprint 1。
- 不为新功能升级 SCHEMA_VERSION 导致清空已有积分；新增表与迁移必须保留旧数据。

## Sprint 1：已有功能可信、规则一致

状态：待实施

目标：修复已有榜单查询失败和未结束题目的信息泄露，使规则、帮助和 ask 回答一致。

### S1-01 统一积分榜数据契约（P0）

- [ ] 核对 leaderboard 返回字段与所有调用方，修复 total / total_score 不一致。
- [ ] 修复 ask 状态快照及排行榜图片失败后的文字兜底。
- [ ] 统一榜单人数配置的默认值与有效范围。
- [ ] 测试空榜、多人有成绩、同分排序、图片渲染失败、异常配置。

验收：真实有成绩时 rank 和 ask 显示一致；排序遵循现有规则：总分降序、解题数降序、首次提交 AC 数降序。排序字段完全相同时不擅自新增胜负规则。图片失败仍可读文字榜单。

### S1-02 统一未结束题目的信息隐藏（P0）

- [ ] 盘点题面、cur、ask、hint、status、榜单、日志转述等用户可见入口。
- [ ] 区分群整体难度进度与当前题目的元数据；明确各入口可公开的内容。
- [ ] 未结束题目的题号、标题、实际 rating、具体分值和来源链接不进入 ask 上下文。
- [ ] 检查题面图片、文件名以及模型提示的元数据，避免旁路泄露。
- [ ] AC / giveup 后按现有约定公开题目信息，不影响揭晓流程。

验收：直接问及诱导 ask 均无法从快照获得受限信息；cur、hint 与两条题目线路同时存在时也保持一致。模型根据题面自行推断难度不等同于元数据泄露，不声称能完全阻止推断。

### S1-03 建立统一规则与功能说明（P1）

- [ ] 从 scoring 的现有常量构造计分与升降档说明，避免复制数值后走样。
- [ ] 整理唯一的功能说明来源，供帮助与 ask 使用，覆盖 hint、ver 和 grm。
- [ ] 新增 rules 命令，直接展示计分、排名、升降档、提示及 grm 规则。
- [ ] 明确当前行为：答错不扣分、同一玩家同题只计首次 AC、群题首个 AC 后结束；hint 群内可见且不扣分；grm 不计分。
- [ ] ask 回答“rank 怎么算”“hint 扣分吗”“怎么升档”时有完整事实依据。

验收：规则数值与实际实现一致；群整体档位说明不暴露当前题目受限元数据；新指令有帮助入口。此任务不调整现有计分策略。

### S1-04 回归与发布（P0）

依赖：S1-01、S1-02、S1-03。

- [ ] 加入有成绩榜单、两槽位同时开题、提示后换题等真实状态场景。
- [ ] 对 ask 检查输入上下文，不能只依靠模拟模型输出证明正确。
- [ ] 验证升级前后玩家积分、题目状态、已出题记忆和提示缓存保留。
- [ ] 完成单元测试、模拟群聊与容器升级验证。
- [ ] 更新 CHANGELOG 与内嵌副本，构建并推送新版本镜像和代码。

Sprint 完成标准：上述全部任务验收通过；提供实际输出示例与验证结果，不留已知阻塞缺陷。

不在本 Sprint：题后解析、申诉、个人训练、周期榜、积分玩法改动。

## Sprint 2：做完一道题后能复盘

状态：规划，Sprint 1 完成后细化。

目标：做题记录和解析可回看，并能说明答案来自哪里。

- [ ] S2-01 定义题目轮次、提交、判词与结果的关联；保留旧记录兼容性。
- [ ] S2-02 新增 sol，只有题目结束后才能查看；区分官方题解链接和模型解析，获取失败时明确提示。
- [ ] S2-03 新增个人 history，分页查看近期题目、判定与得分；正题与 grm 分开。
- [ ] S2-04 记录查看提示的级别与时间，个人战绩区分独立完成和提示后完成，暂不改变积分。
- [ ] S2-05 回归和发布。

验收：同一用户能追溯“做了哪道题、提交什么、为何判定、用了什么提示”；解析不会提前泄露正在进行的题；访问范围与群/用户隔离规则明确。

## Sprint 3：错误可反馈、判定可复核

状态：规划，依赖 Sprint 2 的记录关联。

目标：对错题和争议判定有处理闭环。

- [ ] S3-01 新增 report，保存题面、翻译、公式、答案等问题反馈。
- [ ] S3-02 新增 appeal，关联原提交、原判词与复核结果；添加限流和重复请求控制。
- [ ] S3-03 建立管理员待处理列表及处理状态，保留审计记录。
- [ ] S3-04 问题题目可暂停抽取，修订后再启用。
- [ ] S3-05 回归和发布。

验收：反馈有编号、状态和处理记录；复核模型的意见不自动覆盖历史分数。积分更正涉及哪些人、题目是否重开，须先形成明确策略再实施。

## Sprint 4：坑点题库可持续维护

状态：规划。

目标：有来源、验证和审核的入库流程，逐步提高题库质量。

- [ ] S4-01 候选题与正式题库分离，保存来源链接、采集时间、许可或引用要求及改写记录。
- [ ] S4-02 统一题目结构、稳定 ID 与修订版本；检查重复、答案泄露和分类一致性。
- [ ] S4-03 改进验证器，区分编译、行为验证和依赖 UB 的验证局限；不把未验证直接称为错误或正确。
- [ ] S4-04 分批审核现有未验证条目；合格后入库，有问题的修订或暂停。
- [ ] S4-05 增加专题覆盖统计与入库报告，完成回归和发布。

验收：新题经过候选、验证、审核再发布；来源可追踪，问题可回滚。数量目标根据审核通过率制定，不按生成条数认定完成。

## Backlog：待评估，不承诺交付

| 方向 | 用户价值 | 前置条件或待决定问题 |
|---|---|---|
| 个人训练 | 群题结束后仍能独立练习 | 槽位、计分和群内消息干扰如何隔离 |
| 限时挑战 | 多人做同一题，结束后统一公布 | 答案隐藏、多人提交、结算与重启恢复 |
| 周榜 / 月榜 | 新成员有参与空间 | 可追溯得分流水、周期边界与同分规则 |
| 专题练习 | 定向补弱项 | 分类质量；主动选专题会透露解题方向 |
| 错题重练 | 形成学习循环 | history、复盘记录和已见题标记 |
| 管理员数据备份恢复 | 升级和误操作可恢复 | 权限、恢复预览、数据一致性 |
| 任务状态查询 | 网络慢时知道是否仍在工作 | 生成、翻译、判题任务的生命周期管理 |

约束：QQ 官方机器人不支持随意主动推送；每日任务和定时挑战优先采用用户请求时领取或结算的设计。默认继续面向 2C2G 单容器部署，不引入无明确收益的常驻服务。
