# grm 在线生长（0.16.0）

`grm new` 在开启自动生长且全局冷却到期时，先尝试生成一道新题，再进行常规抽题。默认冷却6小时，最低5分钟；这是按需补充，不是在没有人使用时定时爬网。管理员 `grm grow` 可主动触发同一流程，仍受冷却限制；任何人 `grm growth` 看状态。新题面提示所需的C++标准。

流程：从种子页和可信站点相关链接队列抓一页资料 → 一次模型调用整理原创题 → 另一次模型调用复核来源、解释、驱动和未定义行为 → 隔离验证反例与修复 → 原子保存自动题库 → 题源重新加载。一次采集最多尝试3页，最多生成1题；不会直接执行网页代码。自动生长不是从网页发现现成结构化题库，而是根据资料构造坑点。

来源起点包括OI Wiki竞赛常见错误和C++标准库、cppreference C++20/23页面、LearnCpp vector构造页面；相关链接限制在OI Wiki、cppreference、LearnCpp与isocpp域名的HTTPS页面，重定向重新检查目标。资料有大小与超时限制，一次给模型最多18000字符摘录；部分站点403或跳转不支持时会尝试其他来源，不能保证每个来源始终可访问。

运行数据在插件数据目录的 `pitfall_growth/growth.json`，包含approved、candidates、来源队列、时间和最近结果。新题ID由代码指纹生成，按去空白代码进行去重。批准题须 verified=true 且 review.status=auto_verified；候选不会被正式题源读取。升级镜像保留该文件。损坏文件不自动覆盖或重建，以免抹掉内容。

验证支持g++的c++17/20/23。固定版本和错误版本必须只替换所展示的代码片段，固定程序正常退出且输出匹配，错误程序必须正常退出并产生不同输出，或确实存在编译错误；不把任意崩溃算作验证成功。一次反例仅证明该输入下的现象；模型语义复核也不保证题目绝对正确。

隔离优先bubblewrap，在普通Docker拒绝user namespace时使用Landlock ABI>=3和libseccomp。两种均不可用则候选隔离，绝无无限制运行回退。编译和运行有CPU、内存、进程、文件输出大小和墙钟超时限制；进程组会在完成/超时后清理。Linux Landlock只开放系统工具链只读与临时工作目录，seccomp限制网络、进程访问、挂载、元数据修改等。无需privileged或放宽Docker seccomp。镜像含GCC14、bubblewrap、libseccomp。

配置：`grm_auto_growth` 默认true；`grm_growth_interval_seconds` 默认21600。采集生成及独立复核使用现有模型设置，受judge_timeout_seconds限制。关闭自动生长后管理员仍可主动grow。网络、模型、编译器、标准特性不支持或隔离失败均不影响原题库；运行结果看grm growth，具体异常查日志。

验证包括真实本地和900MiB普通Docker反例运行、Landlock主机文件/写入/网络隔离探针、候选隔离与持久化、去重、权限、冷却及正常群聊流程。没有真实模型凭证的环境使用固定候选测试生成接线，不宣称真实模型已经生成新题。
